# 影视游戏框架 · 参考手册

两块内容长在同一套管线上：

1. **影视游戏**：播一段视频 → 到点弹出选项 → 画面定格 → 玩家选择 → 黑场过渡 → 下一段
2. **调色 / 修图工具链**：同一条后期管线，服务于游戏内视频、编辑器调色台和静态图片修图

Unity 2022.3.62f3 · 内置渲染管线 · Linear 色彩空间 · 旧版 Input Manager

---

## 一、第一次使用

菜单 **Tools → 影视游戏 → 一键搭建全部**，依次完成：

1. 导入 TMP 基础资源（会触发一次程序集重载，重载后**自动继续**，不用再点）
2. 生成中文字体资产并设为 TMP 默认字体 + 全局后备
3. 配置选项按钮底图的九宫格
4. 生成调色材质
5. 生成 `ChoiceButton.prefab` 和 `GameplayUI.prefab`
6. 生成 `Main.unity`，接好全部引用，加入 Build Settings 第 0 位
7. 应用推荐的显示设置（默认窗口化、可调整大小）

> **场景和预制体是代码生成的，不要手改。** 要调布局请改 `Editor/MovieGameSetup.cs`
> 顶部的常数再重跑，否则下次有人重建就把改动冲掉了。

## 二、剧情配置 `StreamingAssets/Story/story.json`

运行时读取，**改完直接 Play 就生效**。

```jsonc
{
  "startId": "v1",
  "titleBgm": "can_i_have_the_day_with_you",
  "transitionDuration": 0.35,

  "segments": [
    {
      "id": "v1",
      "title": "桥段 1",                     // 备注名，只用于日志和占位画面
      "video": "v1.mp4",
      "placeholderSeconds": 66.7,            // 视频没导入时占位画面停留几秒

      "bgm": "can_i_have_the_day_with_you",
      "bgmFade": 2.0,

      "grade": "memory_sepia",               // 调色预设名，留空 = 沿用上一段
      "gradeFade": 2.5,                      // 调色渐变时长，0 = 瞬切

      "loopWhileWaiting": false,
      "loopStart": 0,
      "choiceShowTime": -1,
      "waitVideoEndAfterSelect": false,

      "next": "",
      "choices": [
        { "text": "去电影院吧", "next": "v2" },
        { "text": "去网吧吧", "next": "v2" }
      ]
    }
  ]
}
```

### 字段要点

**`choiceShowTime`** — `-1`（或省略）= 视频播完后出选项，此时已定格最后一帧；填正数 = 播到第 N 秒浮出。

**选项出现即暂停** — 不管哪种时机，选项一出现视频就定在那一帧
（`StoryDirector.pauseVideoWhenChoicesShow`，默认开）。

**`loopWhileWaiting`** — 打开后播到结尾跳回 `loopStart` 继续播，循环到玩家选完。
适用于**片尾本身有可循环的待机镜头**。比如「前 8 秒剧情 + 后 3 秒待机」就填 `loopStart: 8`。
开启时 `pauseVideoWhenChoicesShow` 和 `waitVideoEndAfterSelect` 都不生效。

**`bgm`** — 填名字 = 交叉淡入，**和当前同名时什么都不做**（所以连续几段填同一首 = 不间断）；
留空 = 保持不变；`"none"` / `"stop"` = 淡出停止。

**`grade`** — 填预设库里的名字。配合 `gradeFade` 可以做「回忆段逐渐褪成褒色」这类效果。
插值覆盖 75 个连续参数；曲线、开关这类离散量在过半程时切换。

**`choices`** — 目前最多 2 个（`ChoicePanel.maxChoices` 可改）。空数组 = 播完走 `next`。

配置里写了不存在的 id，加载时 Console 会直接指出是哪一段的哪个选项。

### 还没有视频时怎么测

视频文件不存在时自动切到**占位模式**：顶一张带标题和进度条的画面，按 `placeholderSeconds`
走完这一段，然后照常出选项、走分支。BGM、黑场、`choiceShowTime`、Loop 全都真的在跑。
视频丢进 `StreamingAssets/Videos/` 后自动切回真视频，**JSON 一个字都不用改**。

### 画面为什么能定格在最后一帧

`VideoScreen` 用 **RenderTexture** 输出而不是 `CameraNearPlane`。RenderTexture 在视频停下来之后
仍保留最后一次渲染的内容，配合"播完只 `Pause()` 不 `Stop()`"，画面就停在最后一帧。

### UI 自动寻址

`GameplayUIRoot` 把面板内部的部件集中暴露出来，`StoryDirector` / `VideoScreen` /
`VideoPostProcessor` 在自己引用为空时会自动去取。所以 `GameplayUI.prefab` 拖到任何新场景都能直接用。

选项层挂了 `AspectFollower`，抄视频的 `AspectRatioFitter` 比例——窗口被拉成非 16:9 时按钮不会掉进黑边。

## 五、音频

双 AudioSource 轮换实现交叉过渡，切歌时不会有静音间隙。淡入淡出走 `unscaledDeltaTime`，
`Time.timeScale = 0` 时也不卡住。

四条独立音量，**BGM 和视频音量互不影响**：

| 字段 | 默认 |
|---|---|
| masterVolume | 1.0 |
| **bgmVolume** | **0.5**（压低以免盖住台词） |
| **videoVolume** | 1.0 |
| sfxVolume | 1.0 |

运行中直接在 Inspector 里拖就能听到变化。

> **`rememberPlayerSettings` 开着时，Awake 会用 PlayerPrefs 覆盖上面这些值**，
> Inspector 改了跟没改一样。开发期保持关闭。做玩家设置界面时再打开，
> 滑条绑到 `AudioManager.Instance.BgmVolume` 这类**属性**（属性会自动应用+存档，改字段不会）。

## 六、调色与修图

### 四个入口

**调色台**（`Tools → 影视游戏 → 调色台`）— 停靠到 Game 视图旁边，进 Play 实时调。
调的是场景里那个 `VideoPostProcessor`，素材得在 StreamingAssets 里，定位是"贴着游戏跑"。

**视频台**（`Tools → 影视游戏 → 视频台`）— 独立的视频后期工具。随便哪个路径的视频拖进来，
逐帧看、调色、画质处理，再导出成新的 mp4。不需要场景，不需要进 Play。

**修图台**（`Tools → 影视游戏 → 修图台`）— 同一条管线处理静态图片。导入单张或整个文件夹，
大预览可缩放平移，底部胶片条切换，批量导出。不需要场景，也不需要进 Play。

**运行时面板**（游戏内 `F1`）— 正式包默认禁用，编辑器和开发版可用。

三个编辑器窗口共用 `GradeSettingsGUI`（100+ 参数控件）和 `GradePresetStore`（预设库），
所以在任何一个里调好的 look，存进预设库另外两个都能直接取用。

### 视频台

**播放与定位**：工具栏上是 `|◀ ◀ ▶ ▶ ▶|`（回入点 / 上一帧 / 播放 / 下一帧 / 到出点）。
底部时间轴可拖动，蓝色高亮的是入出点区间，黄线是播放头。旁边能直接敲帧号跳转。

**入出点**决定导出哪一段。「设入点 / 设出点」按当前帧设，「整段」还原成全片。

**导出**走 `ffmpeg 解码 → Unity 调色 → ffmpeg 编码`，两头都是管道，中间不落任何临时文件。
音轨从源文件直接复制（`-c:a copy`），不重编码。质量用 CRF 控制，18 大致是视觉无损。

> 导出这条路**完全不碰 VideoPlayer**。编辑器模式下 VideoPlayer 的逐帧步进能不能稳定
> 触发事件是个未知数，而导出必须确定，所以刻意让它只依赖 ffmpeg。

**两条预览路**，工具栏右侧可切。**默认 ffmpeg**：

| | 顺序播放 | 随机定位 | 说明 |
|---|---|---|---|
| **ffmpeg**（默认） | 6.4 ms/帧 | 133 ms | 常驻解码进程顺序吐帧 |
| VideoPlayer | 由 WMF 决定 | 由 WMF 决定 | 备选。6 秒还准备不好会自动倒向 ffmpeg |

（1080p 实测。片子 24fps 时每帧预算 41.7ms，顺序播放有 6.5 倍余量。）

默认选 ffmpeg 不只是因为快，更因为**它和导出用的是同一个解码器**，预览的颜色和成片
一定对得上。WindowsMediaFoundation 遇到 color primaries 标记缺失的文件会自己兜底，
Unity 日志里那句 `may result in color shift` 就是在说这个。

**定位策略**：能顺着读就顺着读；往前跳 24 帧以内读掉扔掉；跳得远或往回跳才重开进程。
分界线定在 24 是因为顺序读一帧约 6ms、重开一次约 130ms。

**预览分辨率**（工具栏）可降到 1/2 或 1/4。缩放是在管道之前做的，省的是解码和传输量
而不只是 GPU。导出永远是全分辨率——但 Bloom 半径、颗粒粗细、锐化这些和像素尺寸挂钩的
效果，降分辨率预览时会和成片有出入，界面上会提示。

**需要 ffmpeg**。自动探测 PATH 和 WinGet 的包目录，找不到可以在导出栏里手动指定。
没有 ffmpeg 时预览（VideoPlayer 路）照常，只是导不出。

**已知没做**：编辑器里不出声（`audioOutputMode = None`，免得跟场景抢 AudioSource）；
输出宽高必须是偶数，否则 H.264 的 4:2:0 装不下，裁剪时界面会提示。

### 窗口与交互（视频台 / 修图台通用）

两个窗口共用 `GradeCanvas`（画布）、`GradeToolbar`（工具栏）、`GradeSkin`（配色）、
`GradeSettingsGUI`（参数），所以手感是一致的。

**快捷键**

| 键 | 作用 |
|---|---|
| 空格 + 拖拽 | 抓手平移 |
| 滚轮 | 以鼠标为锚点缩放 |
| `F` | 适应窗口 |
| `1` | 100% 原像素 |
| **按住 `\`** | 临时看原图 |
| `←` `→` | 逐帧（视频台） |
| `Home` `End` | 跳到入点 / 出点（视频台） |

> 在参数栏的搜索框里打字时，画布快捷键会自动让位——不然敲 "f" 会被当成「适应窗口」。

**工具栏会自己收纳。** 窗口不够宽时，按优先级从低到高把按钮撤进一个 `⋯` 菜单，
功能一个都不丢。下拉框（解码器、预览分辨率）撤下去会变成子菜单。

> 这是修出来的一个实打实的 bug：原来工具栏用 `GUILayout` 排，固定宽度加起来 934px，
> 而窗口最小宽度才 900px——窗口一窄，右边的按钮就被默默裁掉，点都点不到。
> GUILayout 不会为此报错，它只是把东西挤没。

**布局**

- 右侧参数栏可拖宽、可整体收起（工具栏的「参数栏」开关，或点收起后那条竖边展开）
- **双击竖分隔条**复位到默认宽度
- 底部胶片条（修图台）/ 时间轴（视频台）可收起
- 窗口最小尺寸 520×360，左右分屏也塞得下
- 尺寸和收起状态都存 EditorPrefs，跨会话保留

**底部状态栏**放文件名、尺寸、缩放、当前帧这些。它们原来挤在工具栏中间，
一到窄窗口就把按钮顶掉——信息该待在信息该待的地方。

### 自适应起手值

参数栏的「自适应起手值」。定位是**起点**不是成片——导入一批照片，先让每张各自站住，
再谈风格。曝光 / 色阶 / 高光阴影 / 对比度 / 白平衡五项可以分别关掉。

「对当前这张」和「对选中的 N 张」：后者是**每张按自己的分布各算一套**，
不是把当前这张的参数抄过去（那是上面的「同步」）。

**曝光和色阶要一起解。** 曝光排在色阶前面，可色阶的拉伸会把中位数再推一次——
分开算的话，一张本来就正常的照片会被色阶推到过亮。所以迭代几轮：拿当前曝光定色阶，
再反解出"过完整条链之后中位数落在中级灰"的曝光。

**曝光不能把高光顶出 1.0**，色阶的 `saturate` 在那之后，救不回来。
保住高光优先于把中位数凑准——凑中位数还有色阶和阴影可用，烧掉的高光是彻底没了。

**分析用缩略图**（128 像素）。一张 6000 像素的照片相当于每个缩略图像素平均了两千多个源像素，
分位数在一万六千个样本上已经很稳，而孤立的镜面高光会被平均掉——这恰恰是想要的：
几个反光点不该触发高光回收，大片过曝的天空才该。好处是几百张也是瞬时的。

白平衡默认**关**：日落、烛光这类片子，"中性化"恰恰是把味道抹掉。开了也只打七折。

> 验证：造了六种问题片（欠曝 2 档、过曝 1.5 档、平片雾感、水下偏暗……），
> 量处理前后的中位亮度、四分位距、两端溢出。平片的 IQR 从 0.067 拉到 0.387，
> 欠曝和过曝都拉回中级灰附近，没有一档产生新的溢出。
>
> 判据分两种情况：曝光本来就偏的必须明显拉回来；本来就正常的不许推歪太多、
> 且动态范围利用要变好。**「中位数靠近中级灰」不能当唯一判据**——
> 一张只是发灰的片子，正确处理是抬黑位加反差，中位数反而会往下走。

### 挑片与批处理

胶片条上方是排序 / 筛选 / 全选 / 移出列表。

| 键 | 作用 |
|---|---|
| `←` `→` | 上一张 / 下一张（走的是**筛选后的视图**） |
| `Ctrl` + 点 | 加选 / 取消 |
| `Shift` + 点 | 连选（按**视图顺序**，不是导入顺序） |
| `0`~`5` | 打星，作用于所有选中的 |
| `P` `X` `U` | 留用 / 排除 / 取消标记，同样成批 |

缩略图上：左上角是留用（绿✓）/ 排除（红✕），底边是星级。当前那张是实心蓝框，
同选中的其它张是半透明蓝框——多选时必须一眼看出大图在看哪一张。

**编辑记录会落盘。** 逐图的参数、修补、星级标记都存在
`UserSettings/PhotoGradeEdits.json`，关掉窗口、重启 Unity、改代码触发程序集重载都不会丢。
限流写盘（八秒一次）+ 关窗时强制写一次，所以拖滑条不会每帧写文件。

> 这一条是补的坑：逐图参数最早放在窗口的 `Dictionary` 字段里，
> 而 Unity 序列化不了 Dictionary——**改一行 C# 或者关掉窗口，几十张图的活就全没了**。
> 批处理做得再顺，那样也是个陷阱。
>
> 存在 `UserSettings/` 是因为那是 Unity 约定的"每个人自己的编辑器状态"目录，
> 已经在 .gitignore 里，也不会往你的照片目录里扔 sidecar 文件。
>
> 「清空列表」只清胶片条，**不清编辑记录**——下次把同一批图拖回来，调过的还在。
> 要真清得用参数栏里的「清除全部记录」。

**参数改成逐图的了。** 以前一套参数管所有图，换一张图参数不变。那对"开发一个 look"
很顺手，但一批照片各自曝光不同时就不对了。现在每张有自己的一套，
**新图沿用当前这套当起点**（相当于 Lightroom 的"上一张设置"），所以翻到下一张
不会被打回默认值。参数栏顶上多了复制 / 粘贴 / 同步到选中 / 同步到当前筛选。

**批量导出**跟着走：选中多张就导这些，否则导当前筛选下看得见的那些。
挑完片直接导出留用的那批，这才是挑片的意义。

### 快照

参数栏的「快照」。存整套参数，恢复就是原样盖回去。

**覆盖性操作之前会自动存一份**：重置、胶片化、粘贴、自动色调、载入预设、从调色台复制、
还有恢复快照本身。手动存的用强调色标出来，自动存的是灰的——手动的才是你真正在意的那份。

> Unity 的 `Ctrl+Z` 是会话级的，改一行代码触发程序集重载就没了。
> 而这些操作一下就把整套参数换掉。存一份的成本是几 KB，找不回来的成本是重调一遍。

每张最多 24 份。**满了先挤最老的自动快照**，全是手动的才动手动的——
反过来的话，你手起名的「暖调版」会被一串自动快照挤掉。

上次存快照之后参数没动过的话，不会再存一份，所以连点两次「重置」不会攒出两份一样的。

跟着逐图记录一起落盘（见上面「编辑记录会落盘」），重启 Unity 也还在。

### 导出

| 项 | 说明 |
|---|---|
| 格式 | PNG（无损）/ JPG + 质量 |
| **长边上限** | 0 表示不限。发网上一般 2048 或 1600。「只缩不放」默认开——原图更小时硬拉大只会糊 |
| **命名模板** | `{name}` `{index}` `{index2}` `{index3}` `{total}` `{date}` `{time}` `{rating}` `{w}` `{h}` |
| 子目录 | 留空就直接写到选定目录 |
| **重名时** | 自动加序号 / 直接覆盖 / 跳过 |
| **水印** | 图片或文字，四角任选，大小边距不透明度可调 |

参数栏里有实时的文件名预览，模板写错立刻看得出来，不用等导完一批才发现全乱了。

**水印在最后贴**，在缩放之后——不然它会跟着一起被缩放和调色。用的是
`Graphics.DrawTexture` 走内置的带 alpha 混合的材质，省一个 shader。

**文字水印**自己渲字：`Font.RequestCharactersInTexture` 把要用的字烘进图集，
`Font.GetCharacterInfo` 取每个字形在图集里的 UV，拼成四边形用 `GL` 画出去。
可以指定字体（打中文就选个中文字体）、颜色、字号和描边。

字号按**输出长边**算，所以一批图缩到不同尺寸时，水印的视觉大小是一致的。

> **内置的 `GUI/Text Shader` 用不了。** 它写的是 `Color [_Color]` + `combine primary`，
> 固定管线里那个 primary 是**材质颜色不是顶点色**，`GL.Color` 对它完全无效——
> 拿它画出来的字永远是材质上那个颜色。所以自己配了一个 `Hidden/Love/TextStamp`。

> **描边是往外扩的**，量外框时要把它算进去，否则贴着角的那半圈会被裁掉。

> 线性色彩空间下写进 sRGB 的 RT 时硬件会做一次 linear→sRGB 编码，
> 直接喂界面上选的 sRGB 值等于编码两次，出来发白。所以送进 `GL.Color` 的是 `.linear`。

> **重名判断不能只看磁盘。** 同一批里两张图算出同一个名字时，文件还没落地，
> 第二张会直接盖掉第一张。所以除了 `File.Exists` 还得记一份"这批已经用掉的名字"。

> 星级和标记跟参数、修补存在同一个文件里，见上面「编辑记录会落盘」。

> 「移出列表」只从列表拿掉，不动磁盘上的文件。

### 污点修复 / 仿制图章

去污点、去电线、去路人。工具栏「修复」打开后：

| 操作 | 作用 |
|---|---|
| 点一下 | 去掉这一处，取样源自动找 |
| **Alt + 点** | 设仿制取样点（切到仿制图章模式） |
| 滚轮 | 改笔尖大小 |

画布上有光标环：实线是笔尖，外面那圈虚线是羽化范围。仿制模式下取样点也画出来，
还有一条连线指明从哪儿抄。

**不改原图。** 修补以一串「怎么补」的记录存着，每次变动就从原图重放一遍。
所以能撤销上一处、能整体清除、反复修补也不会累积画质损失。修补按图片路径存，
翻胶片条回来还在。

**自动找源怎么找的**：在目标周围几圈上撒候选点，比的是**环**不是圆盘——
圆盘里就是要去掉的污点，拿它去比会专挑另一个污点当源；而补完之后必须和四周接得上，
所以真正该匹配的是紧挨着圆盘外面那一圈。

**修复和仿制的区别**：仿制是原样搬像素；修复搬完还会整体加一个色调补偿
（目标外圈的平均色减去源外圈的平均色），让补上去的那块和四周的明暗对得上。
不做这一步的话，补上去的会是一块和周围对不上的色斑。

> 试过用低频图做逐像素的频率分离（`healed = src + lowT - lowS`），
> 在真实照片上和常量补偿几乎打平（污点区平均误差 16.5 对 17.0），
> 但要多两趟降采样和一张临时图。简单的那个赢了。
>
> 另外羽化必须**从笔尖边缘往外扩**。往里收的话污点的外圈补不到，会留一圈残影——
> 这个错第一版就犯了，一眼能看出来。

### 蒙版（局部调整）

对标 Lightroom 的蒙版面板。**一个蒙版组 = 若干部件 + 一组自己的调整参数**，
组与组之间互不干扰：压天空一组、提亮人脸一组、单独调地面一组。

| 部件来源 | 说明 |
|---|---|
| 径向 / 矩形 | 椭圆或矩形选区，带羽化 |
| 渐变 | 线性渐变。压天空、提前景全靠它 |
| **画笔** | 手绘。拖拽涂抹，按住 `Alt` 擦除 |
| 颜色范围 | 按色相 + 饱和度圈一块 |
| **亮度范围** | 按亮度圈一块，比如只压高光 |
| **深度范围** | 按远近圈一块，要先生成深度图 |
| **天空** | 自动圈住天空。压蓝天、救过曝的白天空 |
| AI 主体 | 分割模型抠出来的主体 |

#### 天空检测

**不是 AI。** Lightroom 那套是分割模型，这里走的是「从画面顶边往下漫延」的老办法。

因为把天空和蓝衣服、蓝色湖面区分开的关键根本不是颜色，是**连通性**：
天空一定连着画面顶边，衣服不连。纯颜色阈值做不到这一点，漫延能。

三道闸门配合：

| 闸门 | 挡的是什么 |
|---|---|
| 连通 | 只能从顶边一路漫过来。中间那件蓝衣服进不来 |
| 相邻色差 | 卡的是**相邻像素之间**的差，不是跟种子的差 |
| 纹理 | 树梢、屋顶、地平线都是高频，漫到那儿就停 |
| 绿色 | 绿色主导的一律排除。漏进草地是这类检测最常见的失败 |
| 深度上限 | 最多吃到画面的 75%，挡的是天空和水面连在一起 |

> **相邻色差不能换成「跟种子的色差」。** 天空从天顶到地平线本身就是一大片渐变，
> 拿顶端颜色当基准会在半空中截断。

> **亮度闸门量的是 `max(r,g,b)` 不是 luma。** luma 给蓝色的权重只有 0.114，
> 偏振过的深蓝天顶 (30,60,160) 按 luma 算才 0.24，会被当成「太暗」整片丢掉；
> 按 max 算是 0.63，和夜空 (10,12,25) 的 0.10 拉得很开。

> **种子要卡得比漫延严**（纹理阈值减半）。一片有噪点的暗墙面逐点看也有不少地方
> 「够平滑」，拿漫延的阈值筛顶边能攒出足够多的种子，于是室内照片也能「找到天空」。

**算的是源图，搬的是显示空间。** 漫延只跟源图有关，裁剪拉直改多少次都不影响它；
所以这两步分开缓存，拖裁剪框时只重搬一次，不重新漫延。搬的时候用
`DisplayUvToSource` 把两个坐标系对上——和画布吸管用的是同一个函数。

**批量导出时是逐图现算的**，不像 AI 主体蒙版那样只认当前这张。否则「压天空」
这套参数套到整批图上会悄悄什么都不做，那比报错还难查。

找不到天空的情况（从窗户往外拍、顶边全是树枝屋檐）界面上会直说，不会让人
对着一个不起作用的部件调半天。

---

部件之间按**加 / 减 / 交**合成。典型用法：「渐变」加上，再「减」掉主体，
就是只压天空不压人。第一个部件恒按「加」处理——从全黑起步，减和交无从谈起。

每组自带曝光 / 对比度 / 高光 / 阴影 / 饱和度 / 色相 / 染色。
调选区时**务必开「显示」**，把选区以红色叠加出来，靠猜是调不出来的。

**在画面上直接拖。** 几何部件（径向 / 矩形 / 渐变）那一行有个「定位」开关，
打开后画布上就出现形状轮廓和手柄：

| 手柄 | 作用 |
|---|---|
| 黄点（中心） | 移动 |
| 白点 | 改半径。X 和 Y 各一个 |
| 蓝点 | 转角度 |

渐变只有中心和端点两个手柄，端点**同时定方向和跨度**，和 Lightroom 一致。
画三条线：中间实线是半选处，两侧虚线是羽化边界。

> 裁剪模式下画布显示的是未裁剪的整幅，而蒙版坐标是裁剪之后的，两者对不上号，
> 所以那时候不画手柄。

**画笔**那一行的「涂抹」打开后，下面会出现大小 / 硬度 / 流量三根滑条，还有「清空这支笔刷」。
按住 `Alt` 是擦除。流量调低了可以一层层叠出柔和的过渡。

> 视频台不列「画笔」——逐帧手绘跟不住运动，加了也是个用不了的部件。

**实现**

- 部件数量不定，没法在 shader 里展开，所以一个部件跑一趟 Pass，
  结果在两张单通道图之间乒乓累积（Pass 6）
- 蒙版是数据不是颜色，那两张图必须用 `RenderTextureReadWrite.Linear`——
  走 sRGB 的话写进去 0.5 读出来就不是 0.5
- 每组再跑一趟把调整混回画面（Pass 7）。所以 **N 组 = 2N 趟全分辨率 Pass**，
  图片无所谓，视频上组数多了会拖慢预览，界面上有提示
- 风格化（暗角 / 颗粒 / 抖动 / 斑马纹 / 分屏）被挪进独立的收尾 Pass 8，
  排在蒙版之后。否则一块提亮天空的蒙版会连暗角一起提亮——Camera Raw 也是这个顺序
- 笔刷贴图进不了 JSON，由窗口持有，`MaskPart` 只存一个下标；
  尺寸按源图但封顶 2048，蒙版不需要 6100 万像素，放大时 bilinear 反而让边更柔
- 笔迹直接用 `BlendOp Max` / `Min` 画进蒙版，不做乒乓；
  和 `Graphics.Blit` 一样，GL 绘制也不能出现在 `OnGUI` 里，所以只登记、在 `update` 里兑现

> **老预设自动迁移**：早先的 grade.json 里只有单块二级校色（Power Window ∩ HSL 限定器），
> 读进来会自动转成列表里的第一组，效果等价，然后把老开关关掉，免得同一块选区叠两遍。
> 老的二级校色面板仍然保留，还能用。

### 裁剪、拉直、旋转

工具栏「裁剪」进入裁剪模式。**这时画布故意显示未裁剪的整幅**——看不见要切掉什么，
就没法判断裁得对不对。框外压暗，框内画三分线，八个控制点可拖，框内拖动整体平移。

比例预设（1:1 / 4:3 / 3:2 / 16:9 / 9:16 / 2.39:1）在参数栏「裁剪与旋转」里，
旁边还有 90 度旋转、水平/垂直翻转、拉直（±45°）。

几何变换跑在**整条管线的最前面**，所以暗角、Power Window、颗粒都跟着新构图走——
和 Camera Raw 一致，裁完图暗角在新的画面中心，而不是原图中心。

> 色卡标定的四角存在**源图** uv 里，画布显示的却是变换后的画面。两者同时开会对不上，
> 界面上会给出警告。先标定，再裁剪。

### 白平衡吸管与自动色调

**白平衡吸管**：工具栏开启后点画面上一处本该是中性灰的地方，反解出色温和色调。
取 5×5 的平均（单像素的噪点足以让色温差出几百 K），取一次就自动退出。

反解用的是粗到细的数值搜索而不是解析求逆——正向映射里色温经过一个带条件分支的偏移、
色调又经过一条二次曲线，复合之后没有干净的闭式逆。参数只有两个、范围只有 ±1，
扫五轮就收敛到肉眼分辨不出。

> 吸管取的是**调色之前**的源像素。素材开了 LOG 解码或色卡校色矩阵时结果会偏，
> 因为那两步排在白平衡之前而这里没有复现。

**自动色调**：只改曝光和输入黑白点三项，别的一律不碰。曝光把中位亮度推到中级灰，
色阶取 0.2% / 99.8% 两端分位数（不是最小最大值——一两个坏点就能把曲线拽歪）。
统计走 512×512 的缩略图，6100 万像素直接 `GetPixels` 会分配将近 1GB。

### 索尼 ARW

修图台可以直接导入 `.arw`，和 png/jpg 一样拖进去就行。

解码流程：TIFF 目录树 → 找拜耳原始数据 → 黑白电平归一化 → 相机白平衡 →
双线性去马赛克 → 相机色彩矩阵 → sRGB 编码。裁到 `DefaultCropSize`（传感器边上
那圈遮光像素不裁掉会是一条黑边）。

| 选项 | 说明 |
|---|---|
| 半尺寸导入 | 直接用 2×2 拜耳块合成，**不插值，反而比全尺寸更干净**。6100 万像素建议开 |
| 自动曝光归一化 | 把高光推到 0.75。只是一个标量不是曲线，关掉就是相机原始电平 |
| 套用相机色彩矩阵 | 内置 ILCE-7RM4 的系数。要准确颜色就关掉它，用色卡自己解一个 |

**支持两种存储**：

| 相机菜单里的「RAW 文件类型」 | Compression | 状态 |
|---|---|---|
| 未压缩 | 1 | ✅ 12 / 14 / 16 bit |
| 压缩（cRAW） | 32767 | ✅ ARW2 有损 |
| 无损压缩 | 7 | ❌ Lossless JPEG，A1 / A7 IV 之后才有 |

**ARW2 有损压缩**的码流结构：一行里每 16 字节编码 16 个像素，平均正好 8 bit/像素。
这 16 个是**同一奇偶列**上的，所以颜色相同——拜耳阵列里同行隔一列才同色，
于是一组 32 列要用两个 16 字节块，先偶数列再奇数列。

16 字节的位布局（小端 32 位字，低位在前）：

```
bit  0..10   这 16 个像素里的最大值（11 位）
bit 11..21   最小值（11 位）
bit 22..25   最大值落在 16 个里的第几个
bit 26..29   最小值落在第几个
bit 30 起    剩下 14 个各占 7 位，存相对最小值的增量
```

增量只有 7 位而值域有 11 位，所以按块内动态范围左移 `sh` 位（0~3）。
**有损就损在这里**：动态范围大的块步进跟着变粗，平滑渐变上会出现色阶断层。

解出的 11 位值再过一条由标签 `0x7010` 构建的分段曲线（五段斜率 1/2/4/8/16），
还原成线性域。黑电平 128、白电平 4095，和未压缩那条路的 512 / 16383 不是一个域。

> **实现是按公开规范自己写的，没有引用 LibRaw / DNGlab 的代码**——
> 那两个都是 LGPL，而格式本身不受版权保护。

缩略图走机内 JPEG 预览而不是全解码——一张 6100 万像素的 ARW 全解要十秒，
而缩略图只有 128 像素。

**怎么验证的**

- **未压缩** —— ILCE-7RM4A 14bit，和机内 JPEG 预览逐通道比对，
  R/G 与 B/G 比值误差 1% 左右（剩下的差异是机内那条创意曲线）。
- **ARW2 解压核心** —— 和 dcraw 参考实现做差分测试。随机码流、六种画幅宽度
  （含非 32 倍数）、十组随机曲线折点，共 60 组，输出**逐位一致**。
- **ARW2 端到端** —— 把真实 ARW 的原始数据反过来编码成 ARW2、伪造成压缩文件，
  跑完整导入流程，再和未压缩基准逐像素比：平坦区平均误差 0.23/255、
  高对比区 0.68/255，95% 的分量误差 ≤2。误差在高频处更大，
  正是有损压缩该有的特性而不是解码错误。

> 拜耳相位如果错了，红蓝会整体对调、通道比会天差地别。压缩与未压缩两条路
> 解出来的通道比是 1.053/0.882 对 1.054/0.883，说明列交织顺序是对的。

### 色轮怎么工作

RGB 和轮盘位置之间是**可逆投影**（R 在 0°、G 在 120°、B 在 240°），三通道之和恒为 0。
所以色轮**纯粹改色偏、不动亮度**，亮度归主控滑条。展开「显示数值」用滑条微调时，
色轮手柄会同步跟着走。

### LUT

**导入** `.cube` → Texture3D，支持 3D 和 1D，也处理非 [0,1] 定义域。有强度滑条。

**导出**把当前参数烘成 33³ 的 `.cube`。做法是拿单位 LUT 条带图过一遍管线再读回。
烘之前会**把暗角、颗粒、模糊、畸变、蒙版这些依赖坐标的效果清零**——LUT 只能表达 RGB→RGB，
塞进去没有意义，而且会让导出的 LUT 带一圈莫名其妙的暗角。

### 色卡校色

载入一张拍了 24 色卡的照片 → 勾「标定模式」→ 拖四角框住色卡（**黄色手柄是左上角**）→ 解算。

网格用双线性插值定位，**色卡有透视变形也能对上**；采样半径按格子尺寸自动算。

残差 < 0.02 很好，< 0.06 可用，更大说明角点没对准或曝光有问题。

> 求解在**线性空间**做（实测值和参考值都先过 sRGB→线性），因为 shader 里矩阵是在
> LOG 解码之后的线性空间应用的。在 gamma 空间拟合出来的矩阵拿去线性空间用，
> 结果是错的而且很隐蔽。

### AI 主体蒙版

需要 `com.unity.sentis`。修图台里选模型 → 生成蒙版 → 自动跑联合双边精修。

| 模型 | 输入 | 适合 | 授权 |
|---|---|---|---|
| **IS-Net 分割** | 1024px | **人物边缘、发丝，首选** | Apache 2.0 |
| U²-Net 人像分割 | 320px | 人像，兼容性更稳 | Apache 2.0 |
| MiDaS 深度 large/small | 384/256px | 场景远近，**不适合抠主体** | MIT |

拿到蒙版后可做：背景虚化（伪景深）、只锐主体、主体单独调色（和二级校色取交集）。

### AI 降噪

同样需要 `com.unity.sentis`。用的是 **SCUNet 盲降噪**（Apache-2.0），
模型跟仓库一起发，授权和选型依据都写在 `GameAssets/Models/模型授权.md`。

**和 AI 蒙版最大的不同是不能缩图。** 蒙版缩到 1024 再放大回去没关系，蒙版本来就是低频的；
降噪缩一遍等于先把细节丢光，再拿模型去「救」一张已经没救的图。
所以必须原分辨率过——6100 万像素只能切块。

#### 切块

| | |
|---|---|
| 读进模型 | 576×576（模型固定尺寸） |
| 写回画面 | 中间的 512×512 |
| 四周那圈 32px | 只给卷积当上下文，不写回 |

不带上下文直接拼，块边缘会看见**一格一格的网**——卷积在块边界缺邻居。

读窗**恒为 576，贴着画面边缘也不缩水**：这份权重是按固定输入尺寸折叠过的，
尺寸对不上不是慢一点，是直接报形状不匹配。越界的部分镜像补边。

> 补边不能用「夹到边界」——那等于把边缘那一列复制一大片，
> 模型会把这片假的平坦区当成真信号，边上一圈反而更糊。

6100 万像素切成 **247 块**。写回区域拼起来正好铺满整幅、互不重叠，
这条用逐像素覆盖计数验死了（见 `--denoise`）。

#### 分步跑

一帧只跑一块。一口气跑完编辑器要假死好几分钟，分开跑的话每块之间还能响应输入、
能看进度、能取消。取消到一半也不会露出空白——结果图开跑前先铺了一遍原图。

#### 强度

**干净图过一遍模型是 39.9 dB 而不是 99 dB**：它总会抹掉一点东西。
所以强度是可调的混合比，不是开关，实现上就是拿 `DrawTexture` 的 alpha 混合做 lerp
（和贴水印同一个路子，省一个 shader）。

起手值由**实测噪声**给：`NoiseEstimate` 拿二阶差分核量一遍，
亮噪和色噪分开报。别让人对着一张本来就干净的图把强度拉满。

> 噪声估计**分块量、取低分位**。整幅取均值会把纹理当噪声——一片草丛、一堵砖墙，
> 二阶差分同样很大。一张照片总有几块相对平坦的地方（天空、皮肤、墙面），
> 噪声在那些块上量得最准。半幅强纹理的合成图上，估出来是 4.99 而真值 5.00。

#### 降噪排在修补前面

修补是拿周围像素补窟窿。在带噪的图上找取样源，补上去的那块也是带噪的。

#### 没验到的部分

**Sentis 里跑起来是什么样，没验过**——Unity 一直开着，起不了第二个进程。
验到的是：模型算子清单和 Sentis 支持表对得上（`ScatterND`/`Range`/`Expand`
这类最容易出事的已经在折叠时消掉了）、`AiDenoiser` 对着真的 Sentis 2.1.3
程序集编得过、切块和噪声估计的纯逻辑全部通过。

CPU 上一块 576² 要 7.4 秒，247 块就是半小时——**必须用 GPUCompute 后端**。

### 几个实现约定

**色彩空间**：曝光、白平衡、Bloom、色调映射、校色矩阵在**线性空间**做；
色阶、LGGO、对比度、饱和度、曲线、LUT 在 **gamma 空间**做。

**色温色调**走 CIE xy → LMS 的标准白平衡算法，不是简单乘 RGB，调暖时蓝通道不会被压死。

**LOG 解码在管线最前面**——素材还是 LOG 时，曝光和白平衡这些线性运算的前提不成立。

**镜头畸变在细节 Pass 最前面**——它的输出是下游模糊链的输入，这样整条管线天然对齐。

**按需构建**：Bloom、模糊、细节层在参数为 0 时完全不跑；曲线 / 二级 / LUT / 六条曲线 /
HSL 用 shader 关键字在编译期消失。

**HSL 八色带用三角基权重**：每个色带在自己的中心色相处权重为 1，到左右相邻中心衰减到 0，
相邻两条恒好凑成 1。所以色带交界处不会忽强忽弱。八个中心不等距（橙黄挤在前 1/6），
和 Camera Raw 一致——人眼对肤色那一段最敏感。

**接近中性灰的像素不参与 HSL 调整**：`RgbToHsv` 对灰色返回的色相基本是噪声，
不加这道闸门的话灰墙、雪地、白衬衫会被判进某个色带然后染上颜色。

**去朦胧走大气散射模型**：`I = J·t + A·(1-t)`，把 A 取成局部模糊值（那正是糊在景物上的
那层纱），反解得 `J = (I-A)/t + A`。形式上是绕局部均值的对比度拉伸，但强度由透射率
自适应——雾越浓（暗通道越亮）拉得越狠。用模糊值而不是逐像素窗口最小值，是为了绕开
暗通道先验典型的边缘光晕。它**不带饱和度补偿**，通常要配合饱和度一起调。

**几何在最前，白平衡在其后**：裁剪 / 拉直 / 旋转是独立的 Pass 5，跑在细节和调色之前。
C# 端的 `VideoGradeSettings.DisplayUvToSource` 必须和它逐步对应——画布上的吸管和
色卡角点都靠它换算，两边一旦不同步，取色会取到别处的像素，而且偏移往往不大、不容易发现。

## 七、窗口与分辨率

默认**窗口化**，可调整大小。初始尺寸由 `Systems/ScreenSetup` 按桌面算：
取能塞进桌面 80% 区域内的最大 16:9 窗口（2560×1440 桌面 → 2048×1152）。

`F11` 或 `Alt+Enter` 切全屏。窗口状态存 PlayerPrefs；换显示器导致尺寸超出桌面时自动退回默认值。

## 八、字体

**Dynamic 图集**模式：运行时遇到哪个汉字就烘哪个，包里没有几十 MB 的静态图集。

正文用 **Noto Serif SC**（SIL OFL，可随包发布），思源黑体作后备。采样点数 90、边距 9——
宋体这类衬线字横画很细，采样太低 SDF 会把细横糊掉。

**换字体**：ttf 丢进 `GameAssets/Fonts/`，改 `MovieGameSetup.cs` 顶部的路径常数，
跑 **「单步：重建字体资产」**（普通的「生成」有"已存在就返回"的短路，换字体时不生效）。

> 别用 simsun / msyh 等系统商业字体，本地看效果可以，不能随游戏分发。

## 十、常用扩展点

**从中途某段开始调试**：`StoryDirector.debugStartId` 填段 id，Play 直接从那段开始并跳过标题。

**监听剧情事件**：

```csharp
director.onSegmentStart   += seg => Debug.Log($"开始播 {seg.id}");
director.onChoiceSelected += (seg, index) => Debug.Log($"{seg.id} 选了第 {index} 个");
director.onStoryFinished  += () => Debug.Log("流程结束");
```

**跳过当前视频**：`videoScreen.SkipToEnd()`

**改选项布局**：`GameplayUI.prefab` 的 `ChoiceLayer/Container`，或改 `MovieGameSetup.cs` 顶部的
`BtnWidth` / `BtnHeight` / `BtnSpacing` / `BtnBottom` / `BtnFontSize` 后重建。

**标题界面文案**：`TitleLayer` 上 `TitleScreen` 组件的 `gameTitle` / `subtitle` /
`startText` / `quitText`。把 sprite 拖进 `Logo` 子物体就显示图形标题。

**一键胶片化**：两个窗口工具条上的「胶片化」按钮，一次配齐颗粒、暗角、色差、桶形畸变、
只锐对焦区、背景虚化等十几项——**「只锐对焦区」+「背景虚化」是去 AI 感的核心**，
因为 AI 图最大的破绽是全画面等锐、没有焦平面。
